# v1.5 plan: hosted, enterprise-only weekly publishing MCP

**Date:** 2026-10-12 · **Status:** spike ready to run (Brian) · **Tracking:** `ai/BACKLOG.md` → v1.5

The full brief is kept outside the repo, because it describes internal infrastructure. This plan
holds only what the code needs.

## Goal

A Claude scheduled task compiles a weekly brief ("This Week in AI"). One MCP call then:

1. Creates a dated notebook.
2. Adds the brief and key sources.
3. Generates an audio overview.
4. Shares the notebook with a distribution list.
5. Returns the link.

## Constraints

- **Enterprise only.** Gemini Notebook Enterprise (formerly NotebookLM Enterprise) through the
  official Discovery Engine **v1alpha** API. Personal mode is out of scope.
- **Official endpoints only.** No batchexecute, cookies or browser automation. That rules out
  upstream's enterprise batchexecute route (merged in sync batch 4) for v1.5.
- **No Google Drive** anywhere: no Drive sources and no Drive staging.
- **Hosted, not on user devices.** Cloud scheduled tasks reach only remote MCP servers added as
  custom connectors. v1.5 runs as a remote MCP endpoint behind OAuth, single user.
- **v2.0** (out of scope here): multi-user on AWS behind an agent gateway. Each user signs in to
  their own enterprise identity (Okta, then Workforce Identity Federation token exchange).
  v1.5 hosting should be the skeleton for it.

## API facts that shape the design

- There is no list-all or search-by-title, only `notebooks:listRecentlyViewed`. Store the
  `notebookId` at create time.
- A notebook holds **one** audio overview, so the weekly pipeline makes one notebook per week,
  titled `TWAI YYYY-MM-DD`.
- `batchDelete` returns `{}` even for missing names. Use the `name` returned by create.
- Sharing roles: `PROJECT_ROLE_{OWNER,WRITER,READER,NOT_SHARED}`. Recipients need the same
  project, the NotebookLM User IAM role and a license. The API documents no notify flag.
- Website URL sources are blocked in projects with VPC Service Controls. Put article text in
  `textContent` instead.
- The API is Pre-GA. Log full requests and responses from day one.

## Spike (first step)

`scripts/spike_enterprise_v15.py`, run by Brian with his enterprise login:

```
uv run python scripts/spike_enterprise_v15.py --project-number <NUMBER> --share-email <you>
```

It runs the pipeline once:

1. Creates a notebook.
2. Adds a text source and polls until `SOURCE_STATUS_COMPLETE`.
3. Starts the audio overview with `episodeFocus`/`languageCode`/`sourceIds`, falling back to `{}`.
4. Tries `GET` on `audioOverviews/default` and on the returned name.
5. Shares to one email (optionally a group, with `--share-group`).
6. Deletes the notebook (`--cleanup`).

Every call is logged to `~/.notebooklm-mcp-cli/spike-logs/` (token never logged).

## Build phases

1. **Spike** (above). Update this plan with the answers.
2. **Enterprise-only server mode.** One switch that makes the server enterprise-only:
   - Registers only the enterprise tools, so no personal tools, browser login, credential store
     or setup wizard.
   - Refuses personal mode.
   - Never calls batchexecute.

   Keep the code; don't fork it again.
3. **New tools:**
   - `add_text_source` takes multiple items (true `batchCreate`).
   - `create_audio_overview` with the fields, if the spike says they're accepted.
   - Distribution-list config: `list_distribution_lists`, `set_distribution_list`. A local file
     in v1.5; per-user storage in 2.0.
   - `publish_weekly(title, brief, urls[], focus, list_name)`:
     - runs the whole pipeline;
     - waits for sources to complete;
     - retries share per address and reports failures per address;
     - returns the notebook link.
4. **Hosting:**
   - Remote MCP (container or AWS AgentCore Runtime) behind OAuth.
   - Added to Claude as a custom connector.
   - Server-side Google token for the single user (v1.5 only; never a shared service account in
     2.0).
5. **Scheduled task:** a self-contained prompt that compiles the week and calls `publish_weekly`.

**Exit criteria:** three weekly runs in a row, each producing:

- a dated notebook with complete sources,
- a finished audio overview,
- shares applied to every list address,

with no manual steps.
